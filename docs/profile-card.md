# GitHub profile card

V2 implements `GET /api/profile-card.svg`. It is disabled by default; enable only in an explicitly reviewed environment with `PORTFOLIO_PROFILE_CARD_ENABLED=true`. The public GitHub profile README has not been modified. No production routing or deployment is included.

## Data and refresh

Set `PROFILE_CARD_GITHUB_TOKEN` privately on the server. Use a GitHub token with only the access needed for public GraphQL data; do not reuse or expose the OAuth client secret. The request targets only `https://api.github.com/graphql`, with redirects disabled, a three-second connection timeout, an eight-second overall bound and a 64 KiB response bound. Tokens and provider response bodies are not logged or returned.

The fixed query reads `jg-abreu`'s contribution calendar total for GitHub's default last-year collection and the most recently pushed public repository owned by that account. Forks and archived public repositories are not excluded: the label is “latest public repository”, not a curated featured project. Provider identity, count, repository owner, name and privacy are validated; GraphQL errors reject the entire refresh. No private repository names are requested or accepted.

A scheduled background refresh runs on startup and every 15 minutes after the previous refresh completes. Visitors never trigger a GitHub request. The immutable SVG and ETag are replaced atomically. A failed refresh keeps the last good snapshot and its original UTC timestamp; no previous snapshot means “Unavailable”, never an invented count or project. Empty public repository lists explicitly show no public repository. Cache is per process, in memory: restarting loses it. There is no distributed or disk cache in this stage.

The public image uses five-minute browser/shared cache control and supports conditional GET with ETag/304. GitHub's image proxy may retain its own cached copy; the application cannot guarantee an exact refresh time in a README. The SVG uses escaped text, inline shapes, system fonts and no scripts, links, remote fonts or external images. Repository display text is shortened to fit. Headers include `nosniff` and restrictive SVG CSP. Anonymous reads do not create a session; other admin and CSRF protections remain intact.

## Configuration and launch boundary

The endpoint is not registered without the enable flag. Health does not depend on GitHub availability. When enabled without a usable token, the image still renders profile information with unavailable dynamic fields. Static identity, stack, education and “Currently” text match the approved issue; they do not come from generated model content.

Before launch: configure a minimal token privately, verify real GraphQL data and refresh behavior, approve the visual card, confirm the final public API URL and nginx routing, then update the profile README only as part of the authorized joint release. The earlier issue suggests `api.joaoabreu.dev`; this local implementation does not establish or change that hostname. No provisional static card is published.

## Validation — 2026-11-13

Ten focused tests passed, then the complete API suite passed 122 tests with zero failures, errors or skips. Coverage includes malformed/partial/error responses, wrong identity, private repository rejection, missing token, provider failure, bounded response cancellation, cold cache, repeated cache reads without provider calls, last-good preservation/recovery, XML parsing/escaping, ETag/304, response headers and actual Spring Security access with disposable PostgreSQL. Provider calls are simulated; no real GitHub token or quota was used.

A preview generated by the actual renderer with explicitly synthetic contributions and repository name was rasterized locally and visually inspected at 900×380. It is not evidence of live GitHub values or João's visual approval. The existing local review API JAR was not restarted or replaced. Production and main remain unchanged.
